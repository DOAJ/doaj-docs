3. Reject, Resubmit, Unreject

Test context
  • role: admin
  • testdrive: update_request_rejection
Setup:

Use the update_request_rejection testdrive - it supplies journal_3 ('Update Request Rejection - Reject Resubmit Unreject <run_seed>'), an in-DOAJ journal that already has this test's full 'reject, then resubmit' history pre-built: one Update Request already Rejected (titled '...rejected UR (try to unreject this one) <run_seed>') and a second, newer Update Request that is currently open against the same journal (titled '...resubmitted UR (currently open) <run_seed>', status Update Request). Pre-building both avoids two live submissions to the same journal in quick succession, which risks tripping DOAJ's real update-request submission cooldown - this test is about the 'cannot unreject while a newer one is open' guard, not the submissions themselves. OR provide those yourself.

Important: the testdrive page tears down its data as soon as you navigate away from it. Log in and run the test in a separate browser tab/window, leaving the testdrive tab open until you have finished.

ID Action Expected Result  
K.3.1 Confirm the resubmitted Update Request for journal_3 is currently open via the admin area search    
K.3.1.1   The record contains the value "Update Request For: [journal_3 id]"
K.3.2 Locate the older, already-Rejected Update Request for journal_3 (titled '...rejected UR (try to unreject this one)') via the admin area search    
K.3.3 Click "View Finished Update"    
K.3.4 Change the Application Status to "Pending"    
K.3.5 Click "Save"    
K.3.5.1   You receive an error message saying that the Update Request cannot be unrejected
K.3.5.2   Application status remains "Rejected"

4. Reject, Reject, Unreject

Test context
  • role: admin
  • testdrive: update_request_rejection
Setup:

Use the update_request_rejection testdrive - it supplies journal_4 ('Update Request Rejection - Reject Reject Unreject <run_seed>'), an in-DOAJ journal with two Update Requests already Rejected in its history: an older one (titled '...OLDER rejected UR, accept this one <run_seed>', APC $100) and a newer one (titled '...newer rejected UR, ignore this one <run_seed>', APC $250). Pre-building both, already rejected, avoids two live submissions to the same journal in quick succession, which risks tripping DOAJ's real update-request submission cooldown - this test is about proving the older rejected request can still be accepted (and its data wins) even though a newer, also-rejected one exists. OR provide those yourself.

Important: the testdrive page tears down its data as soon as you navigate away from it. Log in and run the test in a separate browser tab/window, leaving the testdrive tab open until you have finished.

ID Action Expected Result  
K.4.1 Locate the OLDER of the two Rejected Update Requests for journal_4 (titled '...OLDER rejected UR, accept this one') via the admin area search    
K.4.2 Click "View Finished Update"    
K.4.3 Change the Application Status to "Accepted"    
K.4.4 Click "Save"    
K.4.4.1   The update request saves successfully
K.4.5 Go to journal_4's ToC    
K.4.5.1   The Journal page shows an APC of $100 (from the OLDER Update Request), NOT $250 (from the newer, ignored, Rejected Update Request)
K.4.6 Search for journal_4's ISSN in the admin journal search    
K.4.6.1   There is only one Journal published in DOAJ with that ISSN
K.4.7 Find the accepted application via the admin search (e.g. filter by Accepted and sort by last updated most recent first)    
K.4.7.1   Update Request says "Produced Journal: [journal id]"
